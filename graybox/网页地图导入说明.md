# 网页地图导入

网页导出地图 JSON 后，在 PowerShell 运行下列命令。将 JSON 路径替换为实际文件；输出路径使用新的文件名，导入器遇到已有文件会停止。

```powershell
& 'D:/Projects/Gamejam/本地工具/godot-4.7.2/Godot_v4.7.2-stable_win64_console.exe' --headless --path 'D:/Projects/Gamejam/灰盒隔离工作区' --script res://graybox/import_web_map.gd -- 'D:/下载/地图.json' 'res://scenes/levels/drafts/网页房间.tscn'
```

导入后在 Godot 打开新场景，检查机关关联，再按 F6 试玩。通过「项目 → 工具 → 将当前房间接入章节」安排房间。

导入器按 32 像素每格生成 World 地形、图片和机关。背景块不创建碰撞；门的关联转换为 plate_paths，出口关联转换为 door_path，移动平台、传送门和颜色记录器使用其命名字段。网页关联线为查看用，节点引用按原有方向导入。颜色记录器会挂为目标机关的子节点。旧大块地形按其覆盖网格铺砖。

当前导入器支持 PNG 及裁切、组件尺寸和上述关联。自定义碰撞矩形、多边形、背景参考图、图层排序、实例旋转翻转和章节清单自动接入尚需扩展。首次导入请在 Godot 检查这些内容；网页 JSON 和项目包仍完整保留设计数据。

## 批量关卡与整章

网页在「关卡库」提供「批量导入 / 导入整章」「批量导出」。导入可多选地图 JSON 或工作室项目 ZIP。整章 JSON 包内含全部图片、五个房间和已编排的顺序，不依赖对方浏览器的本地库。导入前可选择另存副本或按同 ID 新增版本；已有章号的编排会单独确认替换。

在「地图与图层」选择关卡所属章号。章节流程中的四个区域分别固定为第一至第四章，房间可以拖动交换、上移或在下拉框中选择。只编排一章时，其他章可留空。先保存编排，再在同一窗口底部选择章号并导出整章。

批量导入 Godot：

```powershell
python 'D:/Projects/Gamejam/灰盒隔离工作区/graybox/import_web_batch.py' 'D:/下载/整章关卡包.json' 'res://scenes/levels/imported_chapter_02_v1' --godot 'D:/Projects/Gamejam/本地工具/godot-4.7.2/Godot_v4.7.2-stable_win64_console.exe'
```

默认生成新的场景目录及 manifest.json。加上 --install 会将整章按包内章号和顺序写入 frontend/db/catalog.tres，保留对应槽位原有存档 ID，同时备份目录原文件。需要在首次导入时加入该参数；已存在的输出目录会被拒绝。目录安装失败时，场景仍保留，可修复问题后直接运行 install_web_catalog.gd，并传入生成的 manifest.json 重试安装。

批量任务先在项目内暂存。任一关卡生成失败，该批暂存场景会清理；全部成功后才移入新的目标目录。输出目录须位于 res://scenes/levels/ 内，路径不能指向已有目录。章号唯一、每章五间、房间引用和出口方向会在生成前检查。

第一章采用 scenes/levels/old_building/base.tscn，第二章采用 scenes/levels/night_station/base.tscn，包含现有背景、地形材质和自动连边。第三、四章使用通用灰盒模板。模板布景沿用当前项目的一屏布局，自定义超大地图需要进一步调整布景和镜头。房间的导出方向写入元数据，运行时章节切换优先读取该方向。

`past-self-library` 包的 version 为 1。levels 包含 id 和 body（完整地图），chapters 包含 number、title 和 rooms。rooms 的数组顺序即房间顺序，id 引用包内关卡；direction 为 left、right、up 或 down。房间稳定 ID 与排序分开保存。

## 机关开局状态

网页实例属性里的「开局状态」和组件制作里的「默认开局状态」会保存到 props。门使用 initially_open，传送门使用 initially_enabled，拉杆使用 initially_right。单图和批量导入均读取这些字段。

门默认关闭，所有关联条件满足时开启；设置开局开启后，条件满足时关闭，条件解除后恢复开启。重置恢复所配置的开局状态，关门时仍保留玩家防夹检查。传送门的开局启用状态仍受传送目标和开关条件约束；拉杆向右为未激活，向左为激活。

## 第三章方块

工作台自带黑暗遮罩、常亮火把、梯子三种方块，均无地形碰撞，支持在同一格叠放。Godot 导入分别生成 Blackout、Torches、Ladders 图层，梯子图层保留 night_ladders 组。黑暗复用项目的纯黑笔触遮罩脚本，读取玩家、有效虚影、旗子和火把的驱散范围。个人与火把半径默认分别为 [72,100] 和 [128,176] 像素，由第一块黑暗方块的属性设置统一图层参数。第三章风格已接到 dark_building/base.tscn。
