# 移动手感检测与调参方案

> 检测日期：2026-11-20　｜　对象：`scripts/player.gd`（`CharacterBody2D`）　｜　60Hz 物理帧
> 工具：`_reference/tools/measure_feel.gd`、`_reference/tools/sweep_jump.gd`

## 1. 怎么测的

探针直接加载 `scenes/levels/level_01.tscn`，用 `Input.parse_input_event` 注入 A/D/空格，
逐帧读 `velocity` 与 `position`，对同一次操作量「几帧到位 / 走了多远」。

```bash
G="/f/steam/steamapps/common/Godot Engine/godot.windows.opt.tools.64.exe"
"$G" --headless --path . --fixed-fps 60 -s _reference/tools/measure_feel.gd -- --preset=now
"$G" --headless --path . --fixed-fps 60 -s _reference/tools/measure_feel.gd -- --preset=crisp
"$G" --headless --path . --fixed-fps 60 -s _reference/tools/sweep_jump.gd
```

**读数注意**：注入事件在物理帧末生效，所以 `start_vx_f1` 恒为 0，所有读数整体比真实键鼠晚 1 帧。
下文引用时已按「第 1 帧 = 按下那一帧」折算，比较三套参数时口径一致。

真正决定手感钝不钝的是起步曲线和空中阻力，不是重力。

## 3. 三个实测出来的问题

### 3.1 地面起步有 50ms 的"死区"（最严重）

`curve_power = 2.0` 让速度按 `v = 273 × u²` 变化，u 是这段 ramp 的进度：

| 帧 | u | vx | 该帧位移 |
|---|---|---|---|
| 1 | 1/6 | 7.6 | 0.13 px |
| 2 | 2/6 | 30.3 | 0.50 px |
| 3 | 3/6 | 68.3 | 1.14 px |
| 4 | 4/6 | 121.3 | 2.02 px |
| 5 | 5/6 | 189.6 | 3.16 px |
| 6 | 1 | 273.0 | 4.55 px |

前 3 帧没走完 2 个像素，肉眼就是"按了没动"。第 4 帧才明显起步。
更糟的是**空中用的是直线曲线**（`air_curve_power = 1.0`）：同一个方向键，跳起来按立刻有 34 px/s 反应，站在地上按要等 4 帧——
玩家会觉得"地面黏脚、空中反而灵活"，这是最难忍的一类不一致。

来源是注释里那句「参考图那种慢起后快的凹形」。凹形本身没错，错在**拿它做加速**。
凹形的正确用法是减速（先掉得快、尾巴慢慢收），加速段用凹形等于自带输入延迟。

### 3.2 空中松手滑 2.4 格

`air_friction = 400`：满速 273 松手后 23 帧才停，滑行 76.5 px。
这个游戏要踩虚影的头、踩压力板、躲尖刺，落地前 2.4 格的不可控位移会直接变成操作负担——
玩家会形成"空中不敢松手"的习惯，而不是"松手就能定住"。

### 3.3 轻点跳 1.66 格，做不出一格小跳

地图是 32 px 瓦片，`jump_cut = 0.65` → 轻点 53.2 px = 1.66 格。
一格高的台子轻点跳一定过冲，玩家只能改按 3~4 帧去"掐"高度，而抖动 1 帧就差 8 px。
瓦片关卡里"刚好一格"是高频需求，这个必须给到。

## 4. 不用动的部分（别过度调）

- **刹停 3 帧 / 反向到 0 用 4 帧**：已经在"停得住"和"有重量"之间。
- **满跳 115 px / 滞空 47 帧 / 顶点在 51%**：3.6 格高度配 0.78s 滞空是正常值，不是飘。
- **瓦片地面**：满速跑 60 帧 `vx` 恒定 273、站定 60 帧位移 0 —— 没有接缝卡边、没有被挤动。
- **土狼 0.1s / 缓冲 0.12s**：标准值，够用。

## 5. 两套方案（均未采纳，存档备查）

> 2026-11-20 提出。当时实际采纳的是「改跳跃高度 + 压 `jump_cut`」那条线，
> 而它在 11-21 又被回退（见 `docs/跳跃卡手分析.md` 顶部）。
> 所以本节两个方案都没进代码，表里的"现在"列以 §2 的实测为准。
> 如果将来要重做移动手感，这里的逐帧数据仍然可用。

### 方案 A（保守：保留凹形，只压缩时长）

| 参数 | 现在 | A |
|---|---|---|
| accel | 2730（6 帧） | **3600（5 帧）** |
| curve_power | 2.0 | **1.35** |
| air_accel | 2355 | **2900** |
| air_friction | 400 | **550** |
| jump_cut | 0.65 | **0.45** |
| fall_gravity_mult | 1.1 | **1.25** |

实测：第 1 帧 35.3 px/s（13% 满速），前 3 帧 2.1 px，满速 5 帧，空中滑行 52 px，轻点 29.9 px。
改动最小，凹形手感还在，但"按了没动"只是从 4 帧缩到 3 帧。

### 方案 B（推荐：加速改直线，凹形只留给刹车）

| 参数 | 现在 | B |
|---|---|---|
| accel | 2730（6 帧） | **3400（4.8 帧）** |
| curve_power（加速） | 2.0 | **1.0** |
| brake_power（刹车，新增） | — | **2.0（沿用原凹形）** |
| air_accel | 2355 | **3400** |
| air_friction | 400 | **800** |
| jump_cut | 0.65 | **0.45** |
| fall_gravity_mult | 1.1 | **1.3** |

实测：第 1 帧 56.7 px/s（**21% 满速**），前 3 帧 2.8 px，满速 5 帧，空中滑行 **43.5 px**，轻点 **29.9 px**，
满跳仍 115.1 px，助跑跳 6.4 格（比现在近 0.28 格，因为滞空短了 2 帧）。

B 需要一行代码改动：现在 `curve_power` 同时管加速和刹车，得拆成两个参数，
否则改成 1.0 会把"松手先掉得快"的刹车凹形一起抹平。

```gdscript
@export_range(1.0, 3.0, 0.1) var curve_power: float = 1.0   ## 加速段：1 = 直线
@export_range(1.0, 3.0, 0.1) var brake_power: float = 2.0   ## 刹车段：2 = 先掉得快
```
`_approach_speed` / `_shape` 里按 `speeding_up` 分别取用。

**选哪个**：如果"慢起后快"是美术/参考图硬要求，选 A；如果要的是"按了就动、松手就停"，选 B。
两者都不动最大速度、不动跳跃高度，关卡几何不用改。

## 6. 调参之外，手感还缺的四块（按性价比排序）

1. **落地 / 起跳的形变**（0 成本，纯脚本）：现在角色是一张只会眨眼的贴图，起跳、落地、跑动**零视觉反馈**。
   起跳 60ms 拉长 1.12×/压窄 0.9×，落地 80ms 压扁 0.82×/拉宽 1.15×，再 100ms 回弹。
   `character_portrait` 已经有 `fit_to_body()`，加个 `squash(amount)` 即可，不动美术资源。
2. **音效**：全项目 **0 个 `AudioStreamPlayer`**。至少要三个：跳、落地、死。哪怕是最低成本的正弦短音。
3. **死亡节奏**：`death_duration = 1.3s` 淡出 + 重生。谜题游戏一关死 10 次就是 13 秒纯等待。建议 0.7s，或淡出期间按任意键立刻重生。
4. **贴地稳定**：`floor_snap_length` 还是默认 1 px。瓦片平地上没影响（实测无卡边），但以后加斜坡/单向板会需要，先设 8 px 不吃亏。

可选：`physics/common/physics_interpolation = true`。现在是 60Hz 物理直出，在 144Hz 屏上移动和踩虚影会有轻微顿感。开之前要实测虚影逐帧回放会不会抖。

## 7. 风险

- **门高余量只剩 1 px**。示例房间 `complete_room` 的门 160 px 高（y 416~576），玩家 44 px 高站在 y=576 地面，
  实测起跳最高点头顶 **y = 417**，门顶 y = 416，**差 1 px 过不去**，角色被卡在门左侧 x = 800。
  本方案不改跳跃高度所以安全，但**以后任何"跳高一点点"的改动都会直接破关**。
  建议把 `jump_velocity` 从 -610 收到 -602（高度 112 px，余量 4 px），或把门的判定抬 4 px。
  正式房间（`chapter_01_room_02` 等）门只有 128 px 露出地面，余量 13 px，是安全的，两边本来就不一致。
- **助跑跳从 6.68 格降到 6.4 格**。现有房间没有超过 2 格的沟，安全；以后设计跨距时按 6.4 格算。
- 改 `air_friction` 会影响"跳上虚影头"的落点容差，改完必须复跑 21 个 `_reference` 回归测试 + 第一章五间房冒烟。
